# Toolbox 项目上下文

> 给新协作者的紧凑续接入口。产品介绍见 [README](../README.md)，AI 协作边界见 [AGENTS.md](../AGENTS.md)。本文件记录已定方向，**不是运行时状态、CI 结果或部署状态的替代品**；判断当前实现时须读取 `main` 最新源码。

## 产品身份与目前公开范围

- 产品名 **Toolbox**；仓库 `SeekerThinker/toolbox`，默认分支 `main`，当前 README 指向的正式入口为 `https://seekerthinker.github.io/toolbox/`。
- 核心对象是**任务**，不是工具列表。最短路径为“写下任务 → 直接专注 → 完成”；思考、拆解、估时、计划、目标、复盘与元认知建议都是可选能力，不构成依赖链。
- 当前决定只发布**游客版**：无需登录，本地完整可用；PWA 支持离线壳及部分平台的快捷捕获/系统分享，实际兼容性取决于设备和浏览器。
- 当前公开页面 `index.html` 只加载本地能力；邮箱 OTP、同步冲突策略、账号删除及 Supabase 相关文件保留为**未对公众启用的后续准备**。不要把仓库里存在后端代码等同于邮箱登录已上线。
- JSON 备份是游客版的重要数据迁移方式：恢复前确认覆盖；分享内容进入草稿，不进入 URL，也不自动创建任务。不承诺浏览器本地数据能跨设备自动同步。

## 已确认的产品决定

| 决定 | 后续变更时应保护的边界 |
| --- | --- |
| 任务优先、能力可组合 | 不强制“澄清 → 拆解 → 估时 → 才能开始”；创建任务后可直接番茄钟/深度工作。 |
| 游客版作为当前正式版本 | 不渲染账号按钮、不加载云端脚本；以后开放账号需要明确的发布决定与验证。 |
| 未来认证范围只考虑游客与邮箱验证码 | 微信、手机短信、GitHub OAuth 不属于已定的消费者登录方案；邮箱登录目前休眠。 |
| 本地数据由用户掌控 | 登录将来不等于上传；云端与本地冲突必须由用户选择，不可静默覆盖。 |
| 年/月/周/日是时间视野 | 不建立四套任务列表；目标可选，目标设定与长期校准分别负责设定和观察。 |
| 精选方法、少即是多 | 方法库位于任务之后且默认折叠；不为了数量加入通用小工具或独立 Word 模板项目。 |
| 静态、低维护成本 | 当前 HTML/CSS/Vanilla JS + GitHub Pages，不因平台流行就迁移或引入框架。若改变托管，先验证 PWA、子路径、缓存更新与回滚。 |
| 开源与赞助分离 | 保持 MIT；赞助自愿，不解锁功能。`FUNDING.yml` 是仓库入口配置，不代表收款账户必然已获批准。 |

## 当前实现的权威入口

- `index.html` / `tasks.js`：游客首页、任务捕获和直接执行。
- `core.js`：本地存储及 JSON 备份；`tools-thinking.js`、`tools-focus.js`：方法与专注历史。
- `horizons.js` / `calibration.js`：时间视野、目标与跨任务校准。
- `manifest.webmanifest` / `pwa.js` / `capture.js` / `sw.js`：安装、缓存及分享捕获。
- `sync-policy.js`、`sync.js`、`cloud-*.js`、`account-lifecycle.js`、`supabase/`：休眠的账号与云端准备；**不能凭文件存在判断线上启用状态**。
- `.github/workflows/validate.yml` 与 `tests/`：自动化契约。检查最新 `main` 提交对应的 Actions 和 Pages 运行记录，而不是引用过去的绿色结果。

## 尚未用真实使用证据解决的问题

- PWA 被手机系统挂起时，番茄钟到点后的结算、提示与恢复体验；定时值可以恢复，不意味着后台即时通知已经实现。
- 长期重度使用下 `localStorage` 配额及备份/恢复可靠性，尤其跨浏览器和手机设备。
- 真实设备上的 Share Target、安装与离线交互兼容性；CI 的源码/契约检查不能替代设备验收。

以上是**待观察或验证的风险**，不是已确认故障；出现实际证据再决定是否重构。若产品方向、公开范围或上述风险状态发生实质变化，及时更新本文件；普通实现细节由 Git 历史和测试维护，不在此复制流水账。
