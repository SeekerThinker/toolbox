# Toolbox

一个轻量、开源、Local-first 的个人工作方法工具。

**在线使用：** https://seekerthinker.github.io/toolbox/

## 产品模型

Toolbox 的核心不再是“工具列表”，而是 **待办事项**。

一件事情从被记下来开始，之后可以继续拆解、分析、专注和复盘；这些过程都应回到同一条待办下面，而不是散落在不同工具里。

```text
记录一件事
   ↓
待办列表
   ↓
打开某个待办
   ├─ 任务拆解 / 5 Whys / 决策矩阵 / 事前风险推演
   ├─ 番茄钟 / 深度工作计时
   └─ 复盘 / 学习记录
   ↓
形成这件事自己的历史
```

这比单独提供很多小工具更符合长期使用方向。

## 待办

首页首先提供一个轻量待办列表：

- 输入一句话即可新增；
- 区分待办与已完成；
- 每条待办拥有稳定 `taskId`；
- 保存创建、更新时间、完成时间和删除标记；
- 打开待办后再进入思考或专注工具。

数据结构保留 `updatedAt` / `deletedAt` 等字段，是为了后续账号同步时不需要重新设计任务模型。

## 围绕待办使用工具

目前共 **10 个方法工具**。

| 分类 | 工具 |
| --- | --- |
| **思维** | Brain Dump、任务拆解、艾森豪威尔矩阵、加权决策矩阵、5 Whys、事前风险推演、每日 / 每周复盘、费曼学习卡 |
| **专注** | 番茄钟、深度工作计时 |

从某条待办进入工具时，Toolbox 会携带该待办上下文。

思维工具产生结果后，可以直接 **保存结果到待办**；番茄钟和深度工作记录则直接写入对应 `taskId`。

因此一条待办可以逐渐拥有自己的：

- 分析记录；
- 决策与拆解结果；
- 完成番茄数；
- 深度工作时长；
- 时间顺序历史。

## 专注历史

番茄钟记录真正完成的专注段，并保存：

- 完成时间；
- 专注分钟数；
- 所属 `taskId`。

深度工作记录保存：

- 任务内容；
- 开始与结束时间；
- 时长；
- 结束备注；
- 所属 `taskId`。

待办详情会汇总该事项自己的番茄数量、深度工作分钟数和分析次数。

## 数据与账号同步方向

当前数据仍然优先保存在浏览器的 `toolbox:data:v1` 中，同时支持完整 JSON 导出 / 导入。

账号同步是下一层能力，而不是改变产品使用方式：

- 不登录仍然可以完整使用；
- 登录后同步待办、分析、专注历史和偏好；
- 每个任务与记录使用稳定 ID 和更新时间做跨设备合并；
- 登录解决的是迁移、备份和多设备连续性，不应成为使用工具的前置条件。

当前版本 **还没有真正的云端账号服务**，本地备份不会被描述成云同步。

## 使用体验

- 手机和桌面都可以直接新增待办；
- 无需语音输入；
- `/` 快捷键聚焦方法工具搜索；
- 深色模式与响应式布局；
- 数据优先保存在当前浏览器；
- 支持完整数据导出 / 导入。

## 技术结构

```text
index.html         # 待办优先的页面结构
styles.css         # 全部样式
core.js            # 工具注册、统一存储、待办上下文、数据备份
tasks.js           # 待办列表、待办详情、任务历史与工具连接
tools-focus.js     # 任务关联的番茄钟与深度工作
tools-thinking.js  # 拆解、决策、复盘、学习等思维方法
tests/smoke.mjs    # 核心结构检查
```

技术栈：**HTML + CSS + Vanilla JavaScript**。无框架、无 npm 依赖、无构建流程。

## 本地运行

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 静态检查

```bash
node --check core.js
node --check tools-focus.js
node --check tools-thinking.js
node --check tasks.js
node tests/smoke.mjs
```

GitHub Actions 会在 push 和 pull request 时执行这些检查。
