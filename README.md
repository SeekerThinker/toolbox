# Toolbox

一个轻量、开源、Local-first 的个人思考与执行系统。

**在线使用：** https://seekerthinker.github.io/toolbox/

## 产品模型

Toolbox 的核心不是“工具列表”，而是 **一件具体要做的事**。

```text
随手记下一件事
   ↓
澄清完成标准
   ↓
定义下一步动作
   ↓
估时 + 安排开始时间
   ↓
识别障碍 + If–Then 应对
   ↓
需要时调用更深的思维方法
   ↓
番茄钟 / 深度工作执行
   ↓
实际投入与历史记录
   ↓
完成复盘
   ↓
校准下一次判断和工作方式
```

任务、思考、专注和复盘都围绕同一个 `taskId` 累积，而不是散落在多个孤立工具里。

## 任务本身就是工作方法的载体

每条待办现在可以保存：

- **完成标准 `outcome`**：什么结果才算真的完成；
- **下一步动作 `nextAction`**：接下来具体做什么；
- **预计用时 `estimateMinutes`**：执行前的时间判断；
- **计划开始时间 `plannedAt`**：把待办转成明确的行动安排；
- **主要障碍 `obstacle`**：最可能阻止开始或完成的因素；
- **If–Then `ifThen`**：障碍出现时预先约定的应对动作；
- **完成复盘 `reflection`**：实际结果、判断偏差和下次调整。

这些字段吸收了 GTD 的 Next Action、目标澄清、Implementation Intention、时间盒与复盘等方法的共同骨架，但不会要求用户先学习方法名词。

## 元认知引导

Toolbox 不试图替用户思考，而是在任务不同阶段只提示一个更值得问的问题，例如：

- 任务太模糊：**“完成时能看到什么具体结果？”**
- 没有下一步：**“接下来哪个动作可以直接开始？”**
- 没有估时：**“你预计这一步需要多久？”**
- 已知障碍：**“如果它真的出现，你准备怎么应对？”**
- 实际投入明显超过估计：提醒重新拆解或校准估时；
- 任务完成：比较预期、过程和结果，并记录下次调整。

目标不是增加提示，而是逐渐帮助用户看见自己的计划、判断与执行偏差。

## 方法库

方法库仍然存在，但已经降为次级入口，默认折叠。更推荐从具体待办中按需调用方法。

目前共 **10 个方法工具**：

| 分类 | 工具 |
| --- | --- |
| **思维** | Brain Dump、任务拆解、艾森豪威尔矩阵、加权决策矩阵、5 Whys、事前风险推演、每日 / 每周复盘、费曼学习卡 |
| **专注** | 番茄钟、深度工作计时 |

从待办进入方法时会携带任务上下文。思维结果可以保存回待办；番茄钟和深度工作则直接记录对应 `taskId`。

## 专注与实际投入

从任务启动番茄钟或深度工作时，优先使用这条待办的 **下一步动作** 作为本次专注目标，而不是只显示一个模糊的项目名称。

专注历史保存：

- 所属 `taskId`；
- 当时执行的动作；
- 开始 / 完成时间；
- 专注时长；
- 深度工作结束备注。

任务详情会同时显示 **预计分钟** 和 **实际专注分钟**，让估时偏差成为可观察的数据。

## 完成复盘

任务标记完成后，可以记录：

1. 实际结果；
2. 最大偏差 / 学到了什么；
3. 下次遇到类似事情会怎么做。

复盘会作为任务历史的一部分长期保留，而不是生成一次后消失。

## 数据模型与账号同步方向

当前仍然是 Local-first：数据优先保存在浏览器的 `toolbox:data:v1` 中，并支持完整 JSON 导出 / 导入。

任务和历史记录已经按未来同步需要设计：稳定 ID、`updatedAt`、`deletedAt`、`taskId` 关联等字段都已存在。

真正的账号 / 云同步尚未接入。未来原则是：

- 不登录也能完整使用；
- 登录只解决多设备连续性、迁移和备份；
- 同步任务、思考记录、专注历史、复盘和偏好；
- 不把本地备份冒充云同步。

## 页面结构

首页现在优先展示：

1. 快速新增待办；
2. 待办 / 已完成列表；
3. 默认折叠的方法库。

手机端也保持同样逻辑：先记事、再推进，不需要先挑工具。

## 技术结构

```text
index.html         # 待办优先的页面结构
styles.css         # 全部样式
core.js            # 方法注册、统一存储、任务上下文、数据备份
tasks.js           # 待办、澄清、元认知提示、任务历史与复盘
tools-focus.js     # taskId / nextAction 关联的番茄钟与深度工作
tools-thinking.js  # 拆解、决策、风险、复盘、学习等方法
tests/smoke.mjs    # 核心产品模型检查
```

技术栈：**HTML + CSS + Vanilla JavaScript**。无框架、无 npm 依赖、无构建流程。

## 本地运行

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 静态检查

```bash
node --check core.js
node --check tools-focus.js
node --check tools-thinking.js
node --check tasks.js
node tests/smoke.mjs
```

GitHub Actions 会在 push 和 pull request 时执行这些检查。
