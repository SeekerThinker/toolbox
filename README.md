# Toolbox

一个轻量、开源、Local-first 的个人思考与执行系统。

**在线使用：** https://seekerthinker.github.io/toolbox/

## 产品模型

Toolbox 的核心不是“工具列表”，而是 **一件具体要做的事**。

```text
随手捕获一件事
   ↓
澄清完成标准
   ↓
定义下一步动作
   ↓
估时 + 安排开始时间
   ↓
识别障碍 + If–Then 应对
   ↓
需要时调用更深的方法
   ↓
番茄钟 / 深度工作执行
   ↓
实际投入与历史记录
   ↓
完成复盘
   ↓
校准下一次判断和工作方式
```

任务、思考、专注和复盘都围绕同一个 `taskId` 累积。

## 方法不再是孤岛

Toolbox 正在把方法从“独立工具”重构成任务系统本身的能力。

- **Brain Dump → 捕获层**：首页输入框支持一行一件事；一次粘贴多行即可批量进入待办，不需要再打开一个 Brain Dump 工具。
- **艾森豪威尔矩阵 → 待办视图**：每条任务可标记重要 / 紧急，待办列表可直接切换为四象限视图。
- **5 Whys → 原因探索**：不假设第五次追问就是真正根因，而是记录多个原因假设、支持证据、反证 / 其他解释、可控部分和下一步验证。
- **加权决策矩阵 → Decision Journal**：评分只是辅助，还会记录关键假设、当前置信度、改变判断所需的证据、选择理由和回看日期。
- **复盘 → 任务上下文复盘**：会读取原完成标准、下一步、预计用时、实际专注投入和已有分析，再比较预期与实际。

## 一条任务保存什么

每条待办可以保存：

- `outcome`：什么结果算真的完成；
- `nextAction`：接下来具体做什么；
- `estimateMinutes`：执行前估时；
- `plannedAt`：计划开始时间；
- `obstacle`：主要障碍；
- `ifThen`：障碍出现时的预案；
- `important` / `urgent`：用于任务集合的四象限视图；
- `reflection`：实际结果、偏差和下次调整。

## 元认知引导

任务页顶部只给一个 **“现在最值得问”**：

- 任务模糊时，先问完成标准；
- 没有下一步时，要求压缩成可直接开始的动作；
- 没有估时时，先做时间判断；
- 已知障碍时，引导写 If–Then；
- 实际投入明显超过估计时，提醒重新拆解或校准估时；
- 完成后，比较预期、实际和结果。

目标不是替用户思考，而是让计划、判断和执行偏差变得可见。

## 当前方法库

方法库默认折叠，更推荐从具体任务中按需调用。

目前共 **8 个方法**：

| 分类 | 方法 |
| --- | --- |
| **思维** | 任务拆解、Decision Journal、原因探索、事前风险推演、阶段复盘、解释与学习 |
| **专注** | 番茄钟、深度工作计时 |

任务拆解可以把完成标准、下一步和障碍直接写回待办；阶段复盘可以直接更新待办的下一步。

## 专注与历史

从任务启动番茄钟或深度工作时，会优先使用该任务的 `nextAction` 作为本次专注目标，并记录：

- `taskId`；
- 当时执行的 `plannedAction`；
- 开始 / 完成时间；
- 实际时长；
- 深度工作结束备注。

任务详情会显示预计分钟、实际专注分钟、完成番茄数和已保存分析，并把所有记录汇总到同一条时间线。

## 数据与账号同步方向

当前仍然是 Local-first：数据保存在浏览器的 `toolbox:data:v1` 中，并支持完整 JSON 导入 / 导出。

任务与记录已经使用稳定 ID、`updatedAt`、`deletedAt`、`taskId` 等字段，为未来账号同步预留合并基础。

真正的账号 / 云同步尚未接入。原则仍然是：

- 不登录也能完整使用；
- 登录只解决多设备连续性、迁移和备份；
- 同步任务、方法记录、专注历史、复盘和偏好；
- 不把本地备份冒充云同步。

## 技术结构

```text
index.html         # 待办优先的页面结构
styles.css         # 全部样式
core.js            # 方法注册、统一存储、任务上下文、数据备份
tasks.js           # 捕获、待办、四象限、澄清、元认知提示、任务历史与复盘
tools-focus.js     # taskId / nextAction 关联的番茄钟与深度工作
tools-thinking.js  # 拆解、Decision Journal、原因探索、风险、复盘、学习
tests/smoke.mjs    # 核心产品模型检查
```

技术栈：**HTML + CSS + Vanilla JavaScript**。无框架、无 npm 依赖、无构建流程。

## 本地运行

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 静态检查

```bash
node --check core.js
node --check tools-focus.js
node --check tools-thinking.js
node --check tasks.js
node tests/smoke.mjs
```

GitHub Actions 会在 push 和 pull request 时执行这些检查。
