# Toolbox

一个轻量、开源、Local-first 的个人思考与执行系统。

**在线使用：** https://seekerthinker.github.io/toolbox/

## 核心原则

Toolbox 的核心是一件具体要做的事，但**不规定用户必须经过固定流程**。

一个任务最小只需要标题和状态。例如只写“写报告”，就可以立刻开始番茄钟。完成标准、下一步、估时、计划时间、优先级、风险分析、Decision Journal、复盘等全部是可选能力。

产品遵循三个原则：

- **Optional · 可选**：任何环节都不是前置条件；
- **Contextual · 带上下文**：从任务进入任何方法时自动携带已有信息；
- **Composable · 可组合**：某个方法产生的新信息可以无感写回任务，供其他能力继续使用。

任务的复杂度由事情本身决定，而不是由软件决定。

## 从任务到更高层视野

Toolbox 现在有三个尺度，但它们彼此都不是强制关系：

```text
年 / 月 / 周 / 日方向
        ↓ 可选
目标  ←→ 任务 ←→ 思考方法
        ↓
番茄钟 / 深度工作
        ↓
历史记录
        ↓
跨任务元认知洞察
```

最简单的用户可以永远只使用“任务 + 番茄钟”。需要更多结构时，再逐渐接入计划、目标、方法和复盘。

## 年 / 月 / 周 / 日计划

年月周日计划被设计成 **Focus Horizons（时间视野）**，而不是四套重复的待办列表。

每个周期只需要按需记录：

- 这个周期最重要的方向 / 结果；
- 计划或提醒；
- 周期结束后的回顾 / 调整。

系统会自动读取该周期真实产生的数据：

- 完成了多少任务；
- 投入了多少番茄钟 / 深度工作时间；
- 做了多少次目标打卡；
- 本周期完成过哪些任务。

因此计划负责“方向和回顾”，任务仍然只有一份，不需要在日计划、周计划、月计划里重复维护。

## 目标与打卡

目标是任务之上的另一个**可选对象**。

可以创建一个长期目标，例如“稳定运动”“完成论文”“找到新工作”，然后：

- 一键做当天打卡；
- 查看近 7 天和累计打卡次数；
- 可选地把已有待办关联到目标；
- 查看关联任务的完成数量；
- 不再需要时可以归档。

目标没有建立也不会影响任务、番茄钟或任何思维方法的使用。

## 跨任务元认知层

“洞察”不只看单个任务，而是读取长期积累的任务、专注、决策、复盘和目标记录。

目前会观察：

- 近 7 / 30 天完成任务数量；
- 近 7 / 30 天实际专注时间；
- 当前估时与累计专注投入的粗略偏差；
- 多个任务中重复出现的障碍；
- 到了回看日期的 Decision Journal；
- 目标打卡数量；
- 完成任务中保存复盘的数量。

这层只做**事实观察和提示**，不会把相关性包装成因果结论。例如“同一个障碍在 3 个任务中出现”表示它值得进一步验证，并不意味着系统已经认定它是根因。

数据不足时，系统也会明确说数据不足，而不会为了制造“洞察”而要求用户额外填写内容。

## 一个任务可以怎样生长

简单任务可以一直保持：

```text
买牛奶
→ 完成
```

也可以直接：

```text
写报告
→ 番茄钟 25 分钟
→ 完成
```

复杂任务则可以按需逐渐增加：完成标准、下一步动作、估时、计划时间、优先级、障碍 / If–Then、任务拆解、Decision Journal、原因探索、Pre-mortem、专注记录和完成复盘。

这些能力没有固定顺序，可以从任何节点开始，也可以随时切换到另一个节点。

## 任务详情

打开任务后，默认只强调最直接的操作：

- 开始番茄钟；
- 开始深度工作；
- 标记完成；
- 删除。

其他内容采用按需展开：

- **补充任务信息**：完成标准、下一步、估时、计划时间、优先级、障碍、If–Then 和备注；
- **深入思考**：任务拆解、事前风险、Decision Journal、原因探索、阶段复盘、解释与学习；
- **完成后复盘**：只有任务完成后才出现，而且仍然可跳过；
- **历史**：番茄钟、深度工作、分析与复盘都汇到同一条任务时间线。

元认知提示也是建议层，不会阻止用户继续执行。

## 捕获与优先级

首页输入框支持一行一件事，可以一次粘贴多行形成多个待办。

四象限是待办集合的一种可选视图，不是必填步骤。任务只有在用户主动设置优先级后才进入四象限；没有设置的任务保持在“未分类”。

## 当前方法能力

方法库默认折叠，更推荐从具体任务中按需调用。

目前共 **8 个方法**：

| 分类 | 方法 |
| --- | --- |
| **思维** | 任务拆解、Decision Journal、原因探索、事前风险推演、阶段复盘、解释与学习 |
| **专注** | 番茄钟、深度工作计时 |

Brain Dump 已吸收到捕获层，艾森豪威尔矩阵已吸收到任务视图，不再作为独立工具。

## 数据与账号同步方向

当前仍是 Local-first：数据保存在浏览器的 `toolbox:data:v1` 中，并支持完整 JSON 导入 / 导出。

计划、目标和打卡也沿用同一份数据存储，因此以后账号同步时可以和任务、方法记录、专注历史一起迁移。

真正的账号 / 云同步尚未接入。未来仍坚持：

- 不登录也能完整使用；
- 登录只解决多设备连续性、迁移和备份；
- 同步任务、计划、目标、打卡、方法记录、专注历史、复盘和偏好；
- 不把本地备份冒充云同步。

## 技术结构

```text
index.html          # 待办优先的页面结构
styles.css          # 主界面样式
horizons.css        # 时间视野 / 目标 / 洞察样式
core.js             # 方法注册、统一存储、任务上下文、数据备份
tasks.js            # 捕获、待办、四象限、可选能力、任务历史与复盘
horizons.js         # 年月周日计划、目标打卡、关联任务与跨任务元认知
tools-focus.js      # taskId / nextAction 关联的番茄钟与深度工作
tools-thinking.js   # 拆解、Decision Journal、原因探索、风险、复盘、学习
tests/smoke.mjs     # 核心产品模型检查
```

技术栈：**HTML + CSS + Vanilla JavaScript**。无框架、无 npm 依赖、无构建流程。

## 本地运行

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080/`。

## 静态检查

```bash
node --check core.js
node --check tools-focus.js
node --check tools-thinking.js
node --check tasks.js
node --check horizons.js
node tests/smoke.mjs
```

GitHub Actions 会在 push 和 pull request 时执行这些检查。
