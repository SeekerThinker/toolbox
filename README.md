# Toolbox

从一件待办出发，记录、思考、专注、复盘，并持续推进。

**在线使用：** https://seekerthinker.github.io/toolbox/

Toolbox 是一个轻量、开源、Local-first 的个人思考与执行系统。核心对象不是“工具”，而是一件具体要完成的事；思考方法、专注记录、计划、目标和长期校准都围绕同一条任务上下文组合使用。

> 当前公开版本是 **游客版**：打开即可完整使用，数据保存在当前浏览器；不要求注册或登录。

## 核心原则

- **任务优先**：用户先想“我要把这件事做完”，而不是“我要用哪个工具”。
- **可选**：任何环节都不是前置条件；写几个字就可以直接开始番茄钟。
- **带上下文**：从任务进入任意方法时自动携带已有信息。
- **可组合**：拆解、决策、专注、复盘产生的信息继续属于同一个任务。
- **元认知不设门槛**：提示只负责帮助校准，不负责审批用户的流程。
- **Local-first**：当前版本无需账号，核心工作台完整运行在本机。

最简单的路径始终可以是：

```text
写报告
→ 番茄钟
→ 完成
```

更复杂的任务则可以按需接入：

```text
捕获任务
   ↕
任务拆解 / 决策 / 原因探索 / 风险推演 / 学习
   ↕
番茄钟 / 深度工作
   ↓
任务历史
   ↓
复盘与长期校准
```

这些能力是可组合的，不是固定流程。

## 当前能力

### 任务

- 一行一件事，支持一次粘贴多行创建多个待办
- 可选记录完成标准、下一步、估时、计划时间、障碍、If-Then、优先级和复盘
- 打开任务即可直接开始番茄钟或深度工作
- 四象限只是任务集合的一种可选视图，不是独立工作流

### 思考与执行

目前保留 8 个高价值方法：

| 分类 | 方法 |
| --- | --- |
| 思维 | 任务拆解、Decision Journal、原因探索、事前风险推演、阶段复盘、解释与学习 |
| 专注 | 番茄钟、深度工作计时 |

方法库默认折叠，更推荐从具体任务中按需调用。

### 计划、目标与长期校准

年月周日不是四套重复任务列表，而是时间视野：记录当前周期最重要的方向、计划提醒和回顾调整，任务仍然只有一份。

目标是可选的长期对象，可以打卡、关联任务、查看关联任务完成情况和实际专注投入。

长期校准层会比较计划与实际，包括估时偏差、重复障碍、专注时间分布、Decision Journal 回看、周期事实和目标节奏。它只展示证据和趋势，不生成“生产力分数”。计划区不再另设一套重复“洞察”入口。

## PWA 与快速捕获

Toolbox 可以作为 PWA 安装到支持的手机和桌面环境，并支持离线打开核心界面。

在支持 Web App shortcuts / Share Target 的平台上，可以：

- 从应用图标快捷进入“新建待办”
- 从其他 App 分享文字或链接到 Toolbox
- 分享内容通过 Service Worker 的本地临时收件箱带入草稿，不放进 URL，也不会自动创建任务

Web App shortcuts / Share Target 的支持取决于浏览器和操作系统；不支持时普通网页与 PWA 核心功能仍可使用。

## 数据与游客版

当前公开版本不要求账号：

- 所有核心数据保存在当前浏览器本地
- 不登录、不注册即可完整使用任务、思考、专注、计划、目标和校准
- 顶部“备份”可导出完整 JSON，也可以导入备份迁移设备
- PWA 离线后仍可打开核心工作台
- 本地数据不会因为未来增加账号能力而自动上传

仓库中保留了邮箱验证码登录、云端同步、冲突控制和账号删除的后端准备，但这些能力当前不暴露在公开游客版界面。以后启用账号时，仍会遵守“登录不等于自动上传”和“不静默覆盖本机数据”的原则。

## 技术结构

前端保持 **HTML + CSS + Vanilla JavaScript**，无 npm 构建流程。

```text
index.html                       # 待办优先的主界面
core.js                          # 存储、方法注册、任务上下文、导入导出
tasks.js                         # 捕获、待办、任务详情、历史与复盘
tools-thinking.js                # 思考方法
tools-focus.js                   # 番茄钟与深度工作
horizons.js                      # 日 / 周 / 月 / 年方向与目标
calibration.js                   # 长期校准
readability.css                  # 可读性与移动触控尺寸修正
sync-policy.js                   # 预留的多端同步冲突决策
sync.js                          # 预留的邮箱账号与云端 I/O
account-lifecycle.js             # 预留的账号删除生命周期
pwa.js / capture.js / sw.js      # PWA 安装、离线与移动捕获
supabase/migrations/             # 预留的数据库结构、RLS、并发控制
supabase/functions/delete-account/ # 预留的账号删除 Edge Function
tests/                           # 产品模型、PWA、游客版表面和同步契约测试
```

账号相关代码保持休眠；游客版正常使用时不需要用户进行任何云端配置。

## 本地运行

```bash
python3 -m http.server 8080
```

需要验证本地 Supabase：

```bash
supabase start
supabase db reset
```

## 当前方向

当前阶段先把游客版作为完整产品使用，不继续扩展账号体系。优先关注：

1. 真实使用中任务捕获、思考、专注、计划和复盘是否顺畅
2. 移动端快速捕获、离线使用与备份恢复是否可靠
3. 目标、任务和时间视野之间的关联是否自然
4. 随真实样本积累，逐步增强估时和判断校准
5. 邮箱登录与多端同步留待确有需求时再开放
