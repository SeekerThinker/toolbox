# DeskKit · 日常效率与思维工具箱

**少开几个网站，少浪费几分钟，也少在脑子里打转。**

DeskKit 是一个轻量、开源、Local-first 的个人工作台。它把日常最常见的“小摩擦”放到一个地方：处理 PDF、图片、文本和数据，完成日期与单位计算，也帮助你专注、拆解任务、做决策、找根因和复盘。

> 不登录 · 打开即用 · 能在浏览器本地完成的，就尽量不上传

**在线使用：** https://seekerthinker.github.io/toolbox/

---

## 为什么做 DeskKit

很多效率损耗并不来自复杂任务，而来自一天里反复出现的小动作：

- 为了压一张图片，临时搜索一个网站；
- 为了合并 PDF，又打开另一个网站；
- 为了算两个日期之间有几个工作日，再开计算器；
- 明明知道要做什么，却迟迟没有拆成“下一步动作”；
- 面对几个方案来回纠结，却没有一个简单的比较框架。

DeskKit 不想替代 Office、Notion、项目管理软件或专业编辑器。它只做一件事：**把那些几秒到几分钟就该解决的问题，变得更顺手。**

## 一个工作台，四类问题

| 场景 | DeskKit 帮你做什么 | 代表工具 |
| --- | --- | --- |
| **处理材料** | 处理常见文件和图片 | PDF 合并/拆分、图片压缩、OCR、二维码 |
| **整理信息** | 清洗、比较、转换内容 | 文本清理、Diff、CSV、JSON、敏感信息打码 |
| **推进工作** | 减少计算和执行摩擦 | 日期/工作日、百分比、单位换算、写作、番茄钟 |

目前共 **31 个工具**，并持续优先补充高频、轻量、适合浏览器本地完成的能力。

## 工作台体验

DeskKit 不只是把工具放成一排链接，还提供了一层轻量工作台体验：

- `/` 快捷键直接聚焦全局搜索
- 11 个场景分类快速筛选
- 收藏常用工具
- 自动记录最近使用
- 深色模式
- 响应式移动端布局
- 思维与专注记录使用 `localStorage` 保存在当前浏览器
- 无账号体系、无后端数据库、无构建步骤

## 设计原则

### 1. 打开就用

简单任务不应该先注册账号、创建项目或配置工作流。能在一个页面完成，就尽量不多走一步。

### 2. Local-first

文本、表格、图片、PDF、思维记录和专注记录尽量直接在浏览器中处理。对于敏感信息，这比“先上传再处理”更符合 DeskKit 的定位。

### 3. 不只处理文件，也处理思路

效率不只是转换格式和批量处理。注意力、优先级、任务定义、判断和复盘，同样决定了工作是否顺畅。所以 DeskKit 把实用工具和思维工具放在同一个工作台里。

## 隐私与第三方组件

DeskKit 的核心页面没有后端服务。大多数工具完全使用浏览器原生能力运行。

为了避免把大型依赖打包进首页，少数功能会在**第一次打开对应工具时**从 jsDelivr CDN 按需加载开源 JavaScript 组件：

| 组件 | 用途 |
| --- | --- |
| [pdf-lib](https://github.com/Hopding/pdf-lib) | PDF 处理 |
| [Tesseract.js](https://github.com/naptha/tesseract.js) | OCR |
| [QRCode.js](https://github.com/davidshimjs/qrcodejs) | 二维码生成 |
| [jsQR](https://github.com/cozmo/jsQR) | 二维码识别 |

加载组件代码本身不意味着 DeskKit 会主动上传你选择的文件。OCR 还需要在线下载识别引擎和语言模型，因此第一次使用会更慢一些。

> 对极度敏感的数据，建议始终进行人工复核，并根据自己的安全要求决定是否使用浏览器工具。

## 技术结构

项目刻意保持简单：

```text
index.html          # 首页与工具容器
styles.css          # 全局视觉与响应式布局
app.js              # 基础工具与工作台逻辑
v2-core.js          # 数据、计算、隐私等扩展工具
v2-media.js         # PDF、图片、OCR、二维码
v2-fixes.js         # 兼容性修正
v3-register.js      # 思维 / 专注工具注册
v3-focus.js         # 番茄钟、深度工作
v3-thinking-a.js    # Brain Dump、任务拆解、优先级、决策
v3-thinking-b.js    # 根因分析、风险推演、复盘、费曼学习
```

技术栈只有 **HTML + CSS + Vanilla JavaScript**。没有框架，没有 npm 依赖，也不需要构建流程。

## 本地运行

```bash
python3 -m http.server 8080
```

然后访问：

```text
http://localhost:8080
```

建议通过 HTTP / HTTPS 运行，而不是直接使用 `file://`，这样剪贴板等浏览器 API 的兼容性更好。

## 部署到 GitHub Pages

1. 打开仓库 `Settings → Pages`
2. Source 选择 `Deploy from a branch`
3. Branch 选择 `main`
4. Folder 选择 `/(root)`

无需构建，提交到主分支后即可直接发布。
